01 · Complete ownership of the review lifecycle

After · ownership in one place

Review lifecycle module
preparation → agent execution
completion / cancellation → await settlement

Problem
The interface does not guarantee that agents have finished for both returned errors and exceptions thrown by dependencies.
Solution
The runReview implementation owns completion of started tasks before removing the workspace; process mechanics remain internal.
Deletion test
Deleting runReview would move coordination into the UI: this module already has depth. Strengthen its guarantees rather than replacing it with a new shallow module.
Adapter / seam
Existing execution and workspace dependencies allow a controlled test adapter. No additional seam is needed.
Test surface
Through the runReview interface: one reviewer remains active while reading the other’s instructions throws; cleanup happens only after the first finishes. Existing tests cover returned errors and cancellation, but not this sequence.
  • locality: cleanup alongside coordination
  • leverage: one completion guarantee
  • depth: exceptions handled internally

This risk follows from control-flow analysis; it has not been reproduced in an executed test.

Problem
The existing adapter interface covers the catalog, but separate maps select execution behavior; understanding a provider requires moving between modules.
Solution
Gather provider-specific rules with each adapter while retaining the shared process execution module.
Deletion test
run-agent.ts is a shallow selector; deleting it alone moves selection to the caller. Depth increases only when the caller no longer needs to know the builder–parser pair.
Adapter / seam
Codex and Claude are two real adapters, which justify the seam. Do not expand the interface with hypothetical resume support or a plugin registry.
Test surface
Keep launch restriction tests and parser tests; also use the execution interface to verify that each provider’s command, events, and result work together with a controlled process.
  • locality: provider rules together
  • leverage: shared process execution
  • depth: parser selection hidden

Lower priority: the current maps are small and typed. The payoff grows with the next provider protocol change.
